03. 설계 원칙과 기능

AGENTBASE의 기능은 아래 일곱 원칙을 화면으로 구현한 것입니다. 원칙마다 그것을 구현한 메뉴와 기능을 함께 표시합니다.

01운영 서비스까지 한 제품에서

에이전트를 만드는 데서 끝내지 않고 업무 서비스에 연결해 운영하는 데까지 한 제품에서 코드 없이 수행합니다. 구현: 데이터 관리, 데이터 파이프라인 → 파운데이션 모델, 모델 배포 → RAG, 도구 → 워크플로우 → 서비스 API 오픈

02요청에서 시작하는 제작

무엇을 어떤 순서로 만들지 정하지 않아도 업무 요청으로 작업을 시작하고, 실행 전에 사용자가 확인합니다. 구현: 홈의 오케스트레이터(자연어 요청 → 구성안 → 확인 뒤 실행, 작업 이력에 구분 기록)

03오픈 전 수치 확인

모델과 에이전트를 서비스에 오픈하기 전에 품질과 보안을 수치로 확인하고 회차별로 비교합니다. 구현: 모델 배포의 평가와 리더보드, RAG 평가, 워크플로우의 테스트와 보안 평가

04오픈 뒤 통제

오픈한 뒤에도 누가 어떤 범위까지 쓰는지와 자원 사용을 통제합니다. 구현: 서비스 API 오픈의 서비스 연결, 권한 설정, 작업별 모니터링, 작업 이력

05자원과 사람을 하나의 체계로

계정과 자원 한도는 GPUBASE에서 관리하고, AGENTBASE는 그 범위 안에서 작업마다 실행 자원을 정합니다. 구현: GPUBASE 계정 접속, 작업별 실행 자원, 시스템 자원 관리, 크레딧 관리

06데이터는 기관 안에서

학습부터 서비스 API 오픈까지 외부 호출 없이 기관 안에서 완결합니다. 구현: 데이터 관리 업로드, 데이터 파이프라인 수집, 등록한 모델로 하는 파인 튜닝과 모델 배포

07여러 구성원의 안전한 협업

여러 구성원이 함께 작업해도 변경이 충돌하지 않고, 권한 밖의 조작은 관리자 승인을 거칩니다. 구현: 작업 편집 점유, 승인 요청과 알림, 관리 설정의 구성원 권한, 작업 이력 회차

04. 사용자와 하는 일

AI 담당자도메인 데이터로 데이터셋을 만들고 모델을 파인 튜닝해 배포하며, RAG를 만들고 평가합니다.데이터 관리, 데이터 파이프라인, 파운데이션 모델, 모델 배포, RAG

관리자구성원 권한을 부여하고 승인 요청을 검토하며, 자원 사용 현황과 서비스 사용 현황을 확인합니다.대시보드, 시스템 자원 관리, 관리 설정, 크레딧 관리

03. 작업 상태

모든 작업은 아래 상태 중 하나로 표시됩니다. 대기와 실패는 상태 칩을 선택하면 원인을 확인할 수 있습니다.

01생성됨

작업을 만든 뒤 아직 [배포]나 [실행]을 하지 않아 자원을 점유하지 않은 상태입니다.

02대기

자원 부족, 관리자 승인, 지정 시각이나 피크외 시간 때문에 실행을 기다리는 상태이며 상태를 선택하면 대기 사유를 볼 수 있습니다.

03설치중

자원을 할당받아 가져오고 실행 환경을 설치하는 단계이며 이 단계가 끝나면 배포중이나 실행중으로 바뀝니다.

04배포중

배포한 모델 배포, RAG, 도구, 데이터 파이프라인, 워크플로우가 자원을 점유하고 호출을 받을 수 있는 상태입니다.

05실행중

파인 튜닝 학습, 데이터 파이프라인의 전체 실행과 표본 실행, RAG의 검색 DB 생성과 업데이트가 진행되는 상태입니다.

06종료
