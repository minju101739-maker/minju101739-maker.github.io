03. 설계 원칙과 기능

MODELBASE의 기능은 아래 일곱 원칙을 화면으로 구현한 것입니다. 원칙마다 그것을 구현한 메뉴와 기능을 함께 표시합니다.

01데이터에서 배포까지 한 흐름

데이터를 모으고 가공해 학습하고 API로 제공하기까지를 한 제품에서 메뉴 차례대로 진행합니다. 구현: 데이터 관리, 수집, 분석, 라벨링, 전처리 → 데이터 파이프라인 → 모델 학습 → 모델 배포 → 모델 파이프라인

02버전과 회차로 되짚을 수 있게

어떤 데이터로 어떤 모델을 만들었는지 언제든 되짚을 수 있도록 데이터와 실행 결과를 덮어쓰지 않고 쌓습니다. 구현: 원본 데이터 회차, 발행한 뒤 수정할 수 없는 데이터셋 버전, 선택한 버전을 자동으로 바꾸지 않는 대상 데이터, 작업 이력 회차, 계보와 롤백

03한 번 만든 작업은 다시 사용

메뉴에서 만든 작업을 파이프라인의 단계로 불러와 다시 사용하고, 불러온 작업의 설정은 바꾸지 않습니다. 구현: 단계마다 기존 작업 불러오기와 새로 생성, 수집 단계의 실행 일정, 모델 파이프라인의 실행 방식

04코드 없이, 고유한 처리는 코드로

자주 쓰는 처리는 화면의 칸만 입력해 실행하고, 고유한 처리는 직접 작성한 코드를 도커 이미지로 실행합니다. 구현: Built-in 전처리 39종과 Built-in 학습, Custom 전처리와 Custom 학습(도커 이미지와 실행 파일 경로), 개발 환경의 이미지 커밋

05자원은 실행할 때만 점유

작업을 생성해도 자원을 점유하지 않고, 실행과 배포마다 자원을 정해 할당받으며, 잔여가 부족하면 막지 않고 대기시킵니다. 구현: 작업별 실행 자원(노드 풀, GPU, CPU, RAM), 자원 대기와 자동 실행, [배포 중지]와 실행 종료 때 반환, 시스템 자원 관리

06권한 밖의 조작은 승인으로

권한이 없는 조작도 승인 요청으로 진행하고, 관리자가 승인하면 시스템이 요청한 값으로 실행하며 그 과정을 남깁니다. 구현: 구성원 권한 넷(엔드포인트 연결, 다운로드, 컴퓨팅 자원 사용, 라벨링 검수), 승인 요청과 검토, 감사 이력, 알림

07할 수 없는 조작은 이유와 함께

권한이나 상태 때문에 할 수 없는 조작은 숨기지 않고 비활성으로 표시해 이유를 알리고, 여러 구성원이 같은 파이프라인을 동시에 바꾸지 않게 합니다. 구현: 비활성 버튼의 이유 말풍선, 대기와 실패 사유 창, 파이프라인의 편집자와 뷰어

04. 사용자와 하는 일

MODELBASE는 관리자와 AI 개발자가 함께 사용하며, 구분은 GPUBASE 계정의 역할을 따릅니다. 배포한 모델은 엔드포인트를 연결한 외부 서비스가 API로 호출합니다.

사용자하는 일주로 사용하는 메뉴
AI 개발자데이터를 수집하고 라벨링, 전처리해 데이터셋 버전을 발행하고, 모델을 학습해 배포합니다. 권한이 없는 조작은 승인을 요청합니다.데이터 관리, 수집, 라벨링, 전처리, 데이터 파이프라인, 모델 학습, 모델 배포
관리자구성원 권한을 부여하고 승인 요청을 검토하며, 자원 사용 현황과 감사 이력을 확인합니다. 모든 권한을 가집니다.대시보드, 시스템 자원 관리, 리포트, 관리 설정

참고

  • •라벨링의 작업자와 검수자는 구성원 중에서 라벨링 설정으로 지정하며, 검수자는 라벨링 검수 권한이 있는 구성원만 지정할 수 있습니다.
  • •외부 서비스는 MODELBASE 구성원이 아니며, 모델 배포의 API 가이드에 있는 호출 경로와 API Key로 배포를 호출합니다.

07. 작업 상태

01생성됨

작업을 생성한 뒤 아직 [실행]이나 [배포]를 하지 않아 자원을 점유하지 않은 상태입니다.

02대기

자원 부족, 관리자 승인, 실행 일정의 다음 실행 시각을 기다리는 상태입니다. 다음 실행 대기는 자원을 점유하지 않고 실행할 때 할당받습니다.

03설치중

자원을 할당받아 실행 환경을 설치하는 상태이며 설치가 끝나면 상태가 실행중이나 배포중으로 바뀝니다.

04실행중

수집, 분석, 전처리, 학습, 오토라벨링, 파이프라인 실행이 진행되는 상태입니다.

05작업중

작업자와 검수자가 라벨링하는 상태이며 컴퓨팅 자원을 점유하지 않습니다.

06배포중

모델 배포와 파이프라인이 자원을 점유하고 호출이나 실행을 처리할 수 있는 상태입니다.

07종료

실행이 정상으로 끝난 상태입니다.

08중지

구성원이 [중지], [실행 중지], [배포 중지]로 중지한 상태이며 점유하던 자원은 반환됩니다.

09실패

실행이 에러로 끝난 상태이며 상태를 선택하면 실패 사유를 확인할 수 있습니다.

호출 이력Call history배포가 받은 호출 한 건 한 건의 기록입니다. 호출 일시, 호출자, 요청과 출력, 결과를 기재합니다.
호출처Call source배포를 부른 곳의 갈래입니다. API Key(외부 서비스), 배포 테스트(테스트 탭), 오토라벨링(라벨링의 오토라벨링 실행), 파이프라인(데이터 파이프라인 라벨링 단계의 오토라벨링)입니다.
호출자Caller호출을 보낸 주체입니다. API Key 호출이면 요청을 보낸 주소이고, 배포 테스트와 오토라벨링, 파이프라인 호출이면 실행한 구성원입니다.
배포Deployment모델을 워커에 올려 엔드포인트로 호출하게 하는 작업입니다. 등록 유형을 정하고 학습 실행의 모델이나 반입한 Hugging Face 모델로 만듭니다. 배포 상태는 워커 상태로 정합니다.
등록 유형Registration type배포할 모델을 어디서 가져오는지 정하는 값입니다. 학습한 모델(학습과 실행을 고름)과 새 모델 가져오기(출처 Hugging Face, Built-in) 둘입니다. 생성한 뒤에는 바꿀 수 없습니다.
워커Worker배포 안에서 이미지, 모델, 자원을 따로 갖고 호출을 받는 실행 단위입니다. 워커 추가 한 번이 회차 하나이고 워커마다 컴퓨팅 자원을 점유합니다. 배포 상태는 워커 상태로 정합니다.
워커 설정Worker settings롤링 업데이트(최대 추가, 최대 중단, 준비 대기)와 워커 하나의 자원입니다. 저장한 값은 이후에 추가하는 워커부터 적용합니다.
